## Decisions and context missing from the doc

- **Monorepo scope:** a monorepo with shared `core`, `ui` and `mcp` packages applies only inside the Hub. The skills, `opportunities`, `prototype-engine` and client projects stay in separate repos.
- **Vault:** he wants credentials to feel built into the product. The agreed answer is an audited vault (Bitwarden or 1Password) reached through the local helper, with credentials managed from the project page. A fully custom vault could come later, but only after an independent security audit.
- **Chatwoot:** he wants to reuse its working logic. The agreed approach is to run it as a separate service and connect through its API, because its code is Ruby on Rails. Only its core is MIT-licensed, and `enterprise/` is proprietary.

## Security checklist from the research report

The full report is in the original conversation (task `wf-94f671e7-fc46-5dfa-9c64-215c8a973969`) and may not be available in a new session. Its 12-point checklist was written for a Rust/Tauri build and isn't in the doc. Adapted to the current stack, these still apply:

- Commit the lockfile and use locked installs in CI.
- Run one CI gate for formatting, lint, tests, and dependency and license checks, and make it block merges.
- Pin GitHub Actions to full commit SHAs, set minimal `permissions`, and avoid `pull_request_target`.
- Use Dependabot or Renovate, secret scanning with push protection, and a gitleaks pre-commit hook.
- Protect `main` with required CI, PR-only merges and CODEOWNERS on MCP and credential code. Agents must never push to `main`.
- Sign checksums and publish build provenance and an SBOM for anything released.
- Add a `SECURITY.md`, with private vulnerability reporting turned on and actually answered.
- Add an `AGENTS.md` that sets test-first work, "every feature is a command", and a human-approval list for dependencies, licensing, crypto, MCP tool changes and releases.
- Get an independent review of the credential bridge and MCP boundary before storing client credentials, and run prompt-injection tests against the MCP tools.
